# 디자인 규칙 관리

이 스킬은 저장소 루트의 `DESIGN.md`를 유일한 디자인 기준으로 관리한다.
CLAUDE.md 원칙에 따라 규칙을 정하고 리뷰만 하며, 템플릿이나 CSS를 직접 작성·수정하지 않는다.

## 고정 원칙

아래 네 가지는 사용자가 정한 기준이다. 사용자가 명시적으로 바꾸라고 하기 전에는 약화하거나 예외를 늘리지 않는다.

1. 모바일 대응이 원활해야 한다 (모바일 우선, 360px 기준, 터치 영역 48px 이상).
2. 따뜻한 색감으로 구성한다.
3. Pretendard를 메인 폰트로 쓴다.
4. 패딩과 마진은 8px 배수로 둔다.

## 작업 유형

### A. 규칙 추가·변경

1. `DESIGN.md` 전체를 읽고, 바꾸려는 내용이 고정 원칙과 충돌하지 않는지 확인한다.
2. 새 색상은 반드시 명도 대비를 계산해 표에 적는다. 글자는 4.5:1, 큰 글자(24px 이상 또는 19px 이상 굵게)와 입력란 테두리·포커스 표시는 3:1 이상이어야 한다. 계산은 WCAG 상대 휘도 공식으로 스크립트를 돌려 확인하고, 어림짐작으로 적지 않는다.
3. 새 간격·크기 값은 8px 배수인지 확인한다. 테두리 두께, 모서리 반경, 글자 크기만 예외다.
4. 새 컴포넌트는 7절 형식(모양, 크기, 간격, 상태, 접근성)으로 적고, 기존 토큰만 조합한다. 새 토큰이 필요하면 2~5절 표에 먼저 추가한다.
5. 토큰 이름이나 값을 바꾸면 영향을 받는 템플릿·CSS 위치를 찾아 사용자에게 알린다 (직접 고치지 않는다).
6. `DESIGN.md` 맨 아래 `변경 이력`에 날짜와 내용을 추가한다.
7. 폰트 교체, CSS 프레임워크 도입처럼 되돌리기 어려운 결정이면 `adr` 스킬로 ADR을 남기자고 제안한다.

### B. 새 화면 설계

1. 관련 PRD·SRS(`docs/prd`, `docs/srs`)에서 화면의 요구사항을 확인한다.
2. `DESIGN.md`의 컴포넌트를 조합해 360px 화면과 960px 화면의 구성을 글이나 ASCII 목업으로 제시한다.
3. 사용한 토큰과 컴포넌트를 목록으로 적는다. 기존 규칙으로 표현할 수 없는 부분은 A 절차로 규칙 추가를 제안한다.

### C. 템플릿·CSS 리뷰

1. `DESIGN.md` 9절 리뷰 체크리스트와 8절 접근성 체크리스트를 기준으로 본다.
2. 다음을 검색해 위반을 찾는다.
   - 토큰 밖의 색 값: CSS 변수 정의 블록 밖의 `#`, `rgb(`, `hsl(`
   - 8px 배수가 아닌 간격: `padding`, `margin`, `gap`, `width`, `height`의 값
   - `max-width` 미디어 쿼리, 600px·960px 이외의 브레이크포인트
   - 인라인 `style` 속성, `th:utext`, `outline: none`, 16px 미만 입력란 글자
3. 결과는 `파일:라인`, 위반한 규칙(`DESIGN.md` 절 번호), 개선 방향으로 보고한다. 수정 코드는 적용하지 않는다.
4. 가능하면 브라우저 도구로 360px과 960px 화면을 확인하고, 가로 스크롤과 터치 영역을 점검한다.

## 작성 원칙

- `DESIGN.md`는 개발자와 AI 에이전트가 그대로 따를 수 있게, 값과 조건을 표와 목록으로 구체적으로 쓴다.
- "적당히", "여유 있게" 같은 표현 대신 토큰 이름을 쓴다.
- CSS 코드 블록은 넣지 않는다. 토큰 이름, 값, 속성 이름만 적는다.
