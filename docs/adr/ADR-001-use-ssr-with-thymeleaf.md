## 맥락

맛집 리뷰는 검색 엔진에 노출되어야 하고 첫 화면이 빨리 떠야 한다.
프로젝트는 이미 Spring MVC와 Thymeleaf로 구성되어 있고, AI 코딩 도구로 1시간 안에 구현을 마쳐야 한다.

## 결정

우리는 모든 화면을 Spring MVC + Thymeleaf 서버 사이드 렌더링(SSR)으로 만들고, JavaScript 없이 HTML 폼과 링크만으로 동작하게 한다.
REST API와 SPA 프론트엔드는 만들지 않는다.

## 검토한 대안

### 대안 1: REST API + SPA (React 등)
- 장점: 화면 반응이 부드럽고, 이후 모바일 앱과 API를 공유할 수 있다.
- 단점: 프론트엔드 빌드·배포가 따로 필요하고, SEO를 위해 별도 처리가 필요하다.
- 채택하지 않은 이유: 1시간 안에 두 애플리케이션을 만들고 배포하기 어렵다.

### 대안 2: Thymeleaf + htmx 등 부분 갱신 라이브러리
- 장점: SSR을 유지하면서 일부 화면을 새로고침 없이 갱신할 수 있다.
- 단점: 라이브러리 학습과 서버 조각 템플릿 설계가 추가된다.
- 채택하지 않은 이유: MVP 기능은 전체 페이지 이동만으로 충분하다.

## 결과

- 좋은 점: 애플리케이션 하나로 배포가 끝나고, 모든 내용이 HTML에 포함되어 검색 엔진이 읽을 수 있다.
- 감수하는 점: 폼 제출마다 전체 페이지가 다시 그려진다. 가게 찾기도 링크 이동 방식이라 조작 단계가 늘어난다.
- 후속 작업: 쓰기 요청은 PRG 패턴을 지키고, 모든 사용자 입력은 `th:text`로 이스케이프한다.
