## 맥락

로그인은 없지만(ADR-004) 모든 쓰기 요청이 폼 POST라 CSRF 공격에 대비해야 하고, 작성 비밀번호를 안전하게 해시해야 한다.

## 결정

우리는 Spring Security를 도입하되 인증은 쓰지 않는다.
모든 경로를 `permitAll`로 열고, 폼 로그인·HTTP Basic·로그아웃을 끄며, 기본 사용자와 생성 비밀번호가 만들어지지 않게 한다.
CSRF 보호와 기본 보안 헤더는 켜 두고, 작성 비밀번호는 `PasswordEncoder`(BCrypt)로 해시·대조한다.

## 검토한 대안

### 대안 1: Spring Security 없이 직접 구현
- 장점: 의존성이 적고 설정이 필요 없다.
- 단점: CSRF 토큰 발급·검증과 보안 헤더를 직접 만들어야 한다.
- 채택하지 않은 이유: 직접 만든 보안 기능은 실수하기 쉽고 시간이 더 든다.

### 대안 2: `spring-security-crypto`만 사용
- 장점: 비밀번호 해시만 가볍게 해결한다.
- 단점: CSRF 보호가 없다.
- 채택하지 않은 이유: CSRF 보호가 필요하다.

## 결과

- 좋은 점: Thymeleaf 폼에 CSRF 토큰이 자동으로 들어가고, 검증된 해시 구현을 쓴다. 나중에 로그인을 추가하기도 쉽다.
- 감수하는 점: 기본값이 "모든 요청 인증 필요"라서 설정을 빠뜨리면 모든 페이지가 로그인 화면으로 막힌다. 테스트에서 POST마다 CSRF 토큰을 넣어야 한다.
- 후속 작업: 로그인 페이지로 리다이렉트되지 않는지, 토큰 없는 POST가 403인지 테스트로 확인한다.
