# ADR-004: 로그인 없이 닉네임과 작성 비밀번호로 글을 관리한다

## 맥락

첫 버전은 가입 절차 없이 누구나 가볍게 리뷰를 남기게 하는 것이 목표다.
그래도 글쓴이만 자기 글을 고치거나 지울 수 있어야 한다.

## 결정

우리는 회원 계정을 두지 않고, 리뷰·댓글을 쓸 때 닉네임과 작성 비밀번호를 받는다.
수정·삭제 요청은 입력한 비밀번호가 저장된 BCrypt 해시와 일치할 때만 처리한다.
요청 횟수 제한과 비밀번호 실패 잠금은 두지 않는다.

## 검토한 대안

### 대안 1: 회원가입·로그인
- 장점: 작성자 식별이 확실하고 스팸 대응이 쉽다.
- 단점: 가입 장벽이 생기고, 계정·세션 관리 구현이 필요하다.
- 채택하지 않은 이유: 진입 장벽을 낮추려는 PRD 목표와 1시간 개발 목표에 맞지 않는다.

### 대안 2: 소셜 로그인 (OAuth2)
- 장점: 가입 절차가 짧고 비밀번호를 직접 다루지 않는다.
- 단점: 외부 앱 등록과 콜백 설정이 필요하다.
- 채택하지 않은 이유: 외부 설정이 1시간 안에 끝나기 어렵다.

## 결과

- 좋은 점: 누구나 바로 쓸 수 있고, 인증 구현이 단순하다.
- 감수하는 점: 스팸·도배를 막을 장치가 없고, 짧은 비밀번호(4자)를 반복 대입해 남의 글을 지울 수 있다. 비밀번호를 잊으면 글을 고칠 수 없다.
- 후속 작업: 피해가 생기면 비밀번호 최소 길이 상향, 실패 횟수 제한, 요청 횟수 제한, CAPTCHA 순으로 검토한다.
