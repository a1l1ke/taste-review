# ADR-007: 설정값은 환경 변수와 `app.*` 설정 프로퍼티로 주입한다

| 항목 | 내용 |
|---|---|
| 상태 | Accepted |
| 결정일 | 2026-09-17 |
| 결정자 | a1l1ke |
| 대체하는 ADR | - |
| 관련 문서 | [PRD-001](../prd/PRD-001-restaurant-review-site.md) 9절, [SRS-001](../srs/SRS-001-restaurant-review-site.md) REQ-NF-010~014 |

## 맥락

같은 이미지를 로컬, 테스트, Render에서 실행해야 하고, 비밀 값은 저장소에 남기면 안 된다.
사용자는 하드코딩을 가능한 한 피하기를 원한다.

## 결정

우리는 환경마다 다른 값(DB 접속, 포트, 프로필, 풀 크기, 로그 레벨)을 환경 변수로만 주입한다.
업무 설정값(사이트 이름, 페이지 크기, 카테고리 목록, 시간대, BCrypt 강도)은 `app.*` 프로퍼티로 정의하고 `@ConfigurationProperties` 클래스 한곳에서 읽는다.
화면 문구는 `messages.properties`에 둔다.
단, 입력 길이 제한은 DB 컬럼 길이와 맞물리므로 폼 검증 애너테이션에 한 번만 정의한다.

## 검토한 대안

### 대안 1: 값을 코드 상수로 관리
- 장점: 구현이 가장 빠르다.
- 단점: 값을 바꾸려면 다시 빌드·배포해야 하고, 비밀 값이 코드에 섞이기 쉽다.
- 채택하지 않은 이유: 사용자 요구(하드코딩 지양)와 맞지 않는다.

### 대안 2: 입력 길이 제한까지 모두 설정으로 관리
- 장점: 모든 규칙을 배포 없이 바꿀 수 있다.
- 단점: 설정과 DB 컬럼 길이가 어긋나면 저장 시 오류가 나고, 커스텀 검증기가 필요하다.
- 채택하지 않은 이유: 1시간 개발 목표에서 얻는 이득보다 위험이 크다.

## 결과

- 좋은 점: 같은 이미지를 모든 환경에서 쓰고, 비밀 값이 저장소에 남지 않으며, 카테고리 등은 환경 변수로도 바꿀 수 있다.
- 감수하는 점: 설정 키가 늘어나 문서화가 필요하고, 환경 변수를 빠뜨리면 운영에서 시작에 실패한다.
- 후속 작업: 환경 변수와 `app.*` 목록을 배포 문서에 적고, `.env*`를 `.gitignore`와 `.dockerignore`에 추가한다.
