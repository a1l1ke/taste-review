# DEC-001: 기반(A) 구현 결정 기록

- 날짜: 2026-09-17
- 범위: 도메인·설정·보안·DB·마이그레이션·메시지·오류 연계 (B: 웹계층, C: CSS/배포/테스트와 파일 중복 없음)
- 관련: SRS-001 REQ-DATA-001~004, REQ-NF-002~014 / ADR-002, ADR-004~007

## D1. H2 URL: `MODE=PostgreSQL;DATABASE_TO_LOWER=TRUE`
- 이유: 식별자 소문자화로 PostgreSQL 동작에 맞춤. 따옴표 없는 DDL이 양쪽에서 동일하게 실행된다.

## D2. 시각 타입: `Instant` + `TIMESTAMP WITH TIME ZONE`
- `OffsetDateTime` 대신 `Instant`를 쓴다. 항상 UTC로 저장되고 양쪽 DB·Hibernate 6 매핑이 단순하다.
- 화면 표시(`Asia/Seoul`, `yyyy-MM-dd HH:mm`) 변환은 B 영역(템플릿/서비스)에서 `app.display.time-zone`으로 한다.

## D3. Flyway locations: `common` + `{vendor}`
- `spring.flyway.locations=classpath:db/migration/common,classpath:db/migration/{vendor}`.
- H2 실행 시 `db/migration/h2`가 없어도 `fail-on-missing-locations` 기본값(false)으로 무시된다.
- `V1__init.sql`은 공용 SQL만, `V2__pg_trgm_search_indexes.sql`은 `postgresql` 전용이다.

## D4. PK 전략: `IDENTITY` (`GENERATED BY DEFAULT AS IDENTITY`)
- H2와 PostgreSQL(10+) 모두에서 실행되는 공용 DDL을 위해 선택. 시퀀스 공유 문제를 피한다.

## D5. `Review.rating` 자바 타입: `Integer` + DB `INTEGER` (개정)
- 당초 `Short`+`SMALLINT`였으나 웹계층(B)이 전부 `int`/`Integer`로 작성되어 `Integer`+`INTEGER`로 변경.
- `CHECK (rating BETWEEN 1 AND 5)`는 유지되므로 값 범위는 SRS와 동일. `smallint`→`integer` 차이는 1~5 값에 무의미하다.
- `ddl-auto=validate`와 타입 일치를 위해 DDL·엔티티를 같은 타입으로 맞췄다.

## D6. `thymeleaf-extras-springsecurity6` 미추가
- 전부 `permitAll`이라 인증 기반 뷰 분기가 없고, CSRF hidden input은 Thymeleaf+Spring Security 연동으로 자동 포함된다.
- B에서 인증 분기가 필요해지면 그때 추가한다.

## D7. 기본 사용자 생성 방지: `UserDetailsServiceAutoConfiguration` 제외
- `spring.security.user.*` 프로퍼티를 정의하지 않고, 메인 클래스에서 해당 AutoConfiguration을 제외한다.
- Boot 4.1.1에서는 패키지가 `org.springframework.boot.security.autoconfigure`으로 이동했음을 확인(구 `boot.autoconfigure.security.servlet`).
- 시작 로그에 `generated security password`가 없음을 테스트 로그에서 확인한다.

## D11. 웹계층(B) 정렬 (파일 충돌 없이 A 파일만 조정)
- B 서비스가 기대하는 API에 맞춤: 엔티티는 public 기본 생성자+setter(Lombok 최소 `@Getter/@Setter/@NoArgsConstructor` 유지),
- 추가 리포지토리 메서드: `findWithStoreById`(fetch join), `findByStoreIdOrderByCreatedAtDescIdDesc`,
- `findByNameContainingIgnoreCaseOrderByNameAsc`, `CommentRepository.countByReviewIdIn`(집계 1쿼리)+`deleteByReviewId`.
- `app.store.categories`는 `@Value String` 주입(B)과 `List<String>` 바인딩(A) 양쪽이 되도록 CSV 한 줄 문자열로 둔다.
- `messages.properties`에 B의 검증 키 체계(`review.*`, `comment.*`, `*.missing`, `password.mismatch`, `review.deleted`)를 합쳤다.
- `local`·`test`의 `hibernate.dialect` 명시는 Boot 경고(HHH90000025)가 나오지만 H2 PG모드 검증 결정을 위해 유지한다.
- B 동시 작업 중 `compileJava`→`test` 순서로 `./gradlew test` 통과를 확인했다.

## D8. 오류 연계: `GlobalExceptionHandler` + Boot 기본 `/error`
- 별도 `ErrorController`를 만들지 않는다. `BasicErrorController`+`DefaultErrorViewResolver`가
- `templates/error/{404,403,500}.html`(B 영역)을 자동 연결한다.
- 핸들러는 `NoSuchElementException→404`, `AccessDeniedException→403`, 그 외→500 뷰를 반환하고 스택을 노출하지 않는다.

## D9. 정규화 검색: `replace(이름,' ','')` + `lower`
- 탭·개행까지 제거하는 정규식 대신 양쪽 DB 공용 `replace`로 일반 공백만 제거한다.
- 가게 이름은 한 줄 입력이라 충분하다고 판단. 필요시 B/C에서 확장한다.

## D10. Neon 주의
- `pg_trgm`은 신뢰(trusted) 확장이므로 보통 `CREATE EXTENSION`이 되지만, 역할 권한이 없으면 배포 문서 절차(C 영역)로 수동 생성한다.
